# Release v0.4.1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Tag the already-merged issue 41 fix as v0.4.1 by bumping `package.json`, converting the `[Unreleased]` block in `CHANGELOG.md` into the `0.4.1` release entry, and correcting the inaccurate Anthropic-tokenizer claim in `README.md`.

**Architecture:** Three small, scoped, sequential commits — one per file — each independently reviewable and revertable. No code changes; the underlying fix (`50e4209`) is already on the branch. Tagging and publishing are explicitly out of scope and remain user-driven.

**Tech Stack:** Plain `git`, `pnpm check` for verification, `grep` for text assertions. No new tooling, no test additions, no schema regeneration.

---

## File Structure

This plan modifies exactly three existing files and creates zero new files.

| File           | Responsibility for this release                                                                                                                                                            |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `package.json` | Carries the published version string (0.4.0 → 0.4.1). One-line edit.                                                                                                                       |
| `CHANGELOG.md` | Promotes the `[Unreleased]` block to a dated `0.4.1` entry and drops the inaccurate 0.4.0 token-counting bullet. No other bullets move.                                                    |
| `README.md`    | Drops the inaccurate 0.4.0 token-counting bullet and inserts a two-bullet `## What's new in 0.4.1` section between the existing 0.4.0 release notes and `## Development and verification`. |

No new files are introduced. The implementation plan file at `docs/superpowers/plans/2026-07-27-release-v0.4.1.md` and the design spec at `docs/superpowers/specs/2026-07-27-release-v0.4.1-design.md` were produced before this plan was committed and are intentionally not staged for the release.

## Conventions

- All commits in this plan use present-tense imperative subject lines.
- All `git add` commands include the single file being changed in that task. Do not `git add .` or `git add -A`.
- Each task ends with a verification step that produces concrete output (a command and expected result). Do not proceed if the actual output diverges.
- The release commit chain sits on top of `50e4209`. Do not rebase, amend, or rewrite any commit before `50e4209`.
